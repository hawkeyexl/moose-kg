## The 30-second proof

Point moose-kg at a Markdown repo. No config file, no annotation pass, no migration.

```sh
npx moose-kg build
```

```
Wrote kg/graph.ttl (4 docs, 139 triples)
```

That file is canonically sorted Turtle. Build it again and you get the same bytes, so it
diffs cleanly in review and lives in git next to the docs it describes.

Then ask it about your corpus:

```sh
npx moose-kg stats
```

```
Broken internal links (1):
  docs/no-frontmatter.md -> missing.md

Coverage:
  title        4/4  100.0%
  description  1/4  25.0%
```

## What it does, and what it does not

<CardGrid>
  <Card title="moose-kg reads" icon="approve-check">
    Frontmatter fields, heading structure, internal and external links, tags, images, and
    code-fence languages — plus git history, if you let it. It turns those into typed nodes
    and edges with stable IRIs.
  </Card>
  <Card title="moose-kg does not read" icon="close">
    Your prose. Sentences never enter the graph. Every node instead points at the exact span
    on disk that owns them, so you route with the graph and then read the file.
  </Card>
</CardGrid>

<Aside type="note" title="An index, not a corpus">
  This is the one idea worth ten minutes up front. The graph exists to route, filter, audit,
  and attribute — not to store text for retrieval. If you open `graph.ttl` looking for your
  sentences and do not find them, that is the design working.
  [Read why](/moose-kg/concepts/index-not-corpus/).
</Aside>
