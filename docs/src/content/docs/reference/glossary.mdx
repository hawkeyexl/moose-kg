Definitions only. Where a term has a page, this points at it rather than re-explaining it.

## Base IRI

The prefix every minted IRI is built from, set by `baseIri` in config. Defaults to the placeholder
`urn:dockg:`. Changing it rewrites every subject in the graph, so set a real one before anything
consumes the output.

## Broken link

An internal link whose target does not exist on disk, emitted as `dockg:brokenLink` and counted by
`dockg stats`. If your corpus links by published URL rather than file path, see
[route mappings](/dockg/build/routes/) before treating these as real.

## Broken section ref

A `kg.sections` key matching no heading in the document, emitted as `dockg:brokenSectionRef`.
Almost always a renamed heading.

## Closed shape

A SHACL node shape declaring `sh:closed true`: any predicate it does not name is a violation. Every
dockg node shape is closed, so the emitted graph cannot grow an unagreed predicate silently.

## Concept

A `skos:Concept` node, minted from a `kg.label`, `tags`, or `concepts` value. Concept IRIs come
from the slugified label, so two spellings converge on one node.

## Coverage

The fraction of documents carrying a given metadata field, over twelve document fields, plus a second, ungated table over sections. Reported by
`dockg stats` and gated by [thresholds](/dockg/govern/coverage/) under `--check`.

## CUJ

Critical user journey. A complete outcome a reader must be able to reach. dockg's documentation is
organized around these rather than by document type; they live in `docs/content_strategy/journeys/`.

## Derive source

One of the seven things dockg reads: `frontmatter`, `sections`, `links`, `tags`, `images`, `code`,
`provenance`. All on by default, controlled by `build.derive`.

## Determinism

The contract that two builds over unchanged inputs produce byte-identical output. See
[determinism](/dockg/concepts/determinism/).

## Edge contamination

Retrieval returning content from the wrong product, variant, or version because it is semantically
close to the right content. The failure a typed graph prevents deterministically and a ranker
cannot.

## Frontmatter

The metadata block at the top of a Markdown file, between `---` lines. dockg reads YAML; TOML and
JSON fences are an operational error for `fill`. See the
[frontmatter reference](/dockg/reference/frontmatter/).

## Graph guardrail

The check `dockg fill` runs before writing a proposed field: simulate its triples against the SHACL
shapes and reject anything that would corrupt the graph. Rejections are routine and exit `0`.

## iiRDS

The intelligent information Request and Delivery Standard, from tekom — the technical-communication
industry's RDF vocabulary for documentation semantics. dockg references its published IRIs for topic
typing, product applicability, lifecycle phases, and subjects. Licensed CC BY-ND, so the vocabulary
is referenced and never vendored.

## IRI

Internationalized Resource Identifier — the stable identity of a node. A document's is its
repo-relative path under the base IRI; a section's is its document's plus the heading slug as a
fragment.

## `kg:` versus `dockg:`

`kg:` is the **frontmatter key** you write in Markdown. `dockg:` is the **RDF namespace prefix**
(`https://hawkeyexl.github.io/dockg/ns#`) in the emitted graph. Not the same thing, and easy to conflate.

## Negative scope

An explicit assertion that something does **not** apply — `kg.not-applicable-to` and
`kg.not-about-product-aspect`. Necessary because [absence means unknown](/dockg/concepts/open-world/).

## Open-world semantics

The assumption that a missing value means *unknown*, not *false*. A query treating absence as
exclusion returns a set that is wrong in the dangerous direction.

## Orphan document

A document with no inbound or outbound `dcterms:references`. Reported by `dockg stats`.

## PROV-O

The W3C provenance ontology. dockg uses it for authorship, derivation, revision, and the qualified
attribution and association nodes that distinguish a human author from a tool from a model.

## Qualified attribution

A PROV-O node carrying a role alongside an agent, so the graph distinguishes who authored, what
generated, and which tool built — rather than collapsing them into one `creator` string.

## Route mapping

Configuration telling dockg how published site URLs map back to source files, so site-style links
become real graph edges. See [map your site's routes](/dockg/build/routes/).

## Section

A `dockg:Section` node, one per heading, whose IRI addresses an exact span on disk. Metadata can be
attached per section via `kg.sections`.

## SHACL

Shapes Constraint Language — the W3C standard `dockg check` validates the assembled graph against.
See [validation rules](/dockg/reference/shapes/).

## SKOS

Simple Knowledge Organization System — the W3C vocabulary for concepts and their relationships.
dockg maps `kg.label` and its dependents onto it.

## Slug

A heading or label reduced to a URL-safe identifier, GitHub-style. Section keys and concept IRIs
both derive from slugs, which is why renaming a heading can orphan its metadata.

## Turtle

The RDF text serialization dockg emits. Canonically sorted, with no blank nodes, so it diffs cleanly
in git.

## Vector sidecar

`kg/vectors.<lang>.bin` — the optional embedding artifact beside the graph and that language's
search index, one per localization. Refused rather than used when its model, dtype, dimensions,
language, or corpus digest disagree with the index.
