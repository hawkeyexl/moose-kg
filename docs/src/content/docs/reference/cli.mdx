dockg exposes eleven commands. All of them except `init` read a `dockg.config.yaml` if one is
present, and every path they take on the command line resolves against your **current working
directory**.

<Aside type="caution" title="Run dockg from the repo root">
  Input globs are resolved against the working directory, not against the config file's location.
  Running from a subdirectory matches nothing and says so:

  ```
  dockg: No input files matched: docs/**/*.md (cwd: /repo/docs)
  ```
</Aside>

## Global options

| Option | Description |
|---|---|
| `-V, --version` | Print the version and exit |
| `-h, --help` | Print help for the program or a command |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success, or findings that do not gate |
| `1` | Findings — validation failures, `check` violations, `stats --check` breaches |
| `2` | Operational error — bad input, missing file, unusable environment |

The details are less obvious than the table suggests; see
[Output & exit codes](/dockg/reference/output-and-exit-codes/).

## `init`

Create a starter `dockg.config.yaml` in the current directory. Refuses to overwrite an existing
one.

```sh
dockg init
```

```
Created /repo/dockg.config.yaml
```

Exits `2` if the file already exists.

## `build`

Derive the knowledge graph and write deterministic Turtle.

### Arguments

| Argument | Description |
|---|---|
| `globs` | Input globs (default: config inputs) |

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-o, --out <path>` | Output `.ttl` path (default: config `out`) |

### Examples

```sh
dockg build                                     # config inputs, config out
dockg build "docs/**/*.md" --out kg/docs.ttl    # override both
```

```
Wrote kg/graph.ttl (4 docs, 139 triples)
```

Exits `0` on success — including a degraded build that warned about unavailable git history.
Exits `2` when no input file matches, or when `provenance.git: true` and git is unusable.

## `check`

Validate the built graph against the dockg SHACL shapes (violations exit 1).

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `--shapes <paths...>` | Shapes `.ttl` files (default: config `check.shapes`, then bundled) |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

### Examples

```sh
dockg check
dockg check --format json
```

```
warning: https://example.com/kg/concept/installation skos:prefLabel — concept carries multiple prefLabels (same slug, different spellings) — settle on one spelling [docs/configuration.md, docs/getting-started.md]

0 violations, 2 warnings
```

Exits `1` if any finding is a violation. **Warnings and info exit `0`** — the run above exits `0`.

## `validate`

Check docs are KG-ready (frontmatter validated via docmeta).

### Arguments

| Argument | Description |
|---|---|
| `globs` | Input globs (default: config inputs) |

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

Files are discovered with dockg's own mechanism and then handed to docmeta as an explicit list,
so `validate` covers exactly what `build` would ingest. With no `validate.schemas` configured it
uses the frontmatter schema bundled with the package.

Exits `1` when any file fails or errors; `2` when the inputs include a file type docmeta cannot
validate.

## `fill`

Propose `kg:` frontmatter fields with an LLM, gated by confidence, and write them back.

### Arguments

| Argument | Description |
|---|---|
| `globs` | Input globs (default: config inputs) |

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |
| `--dry-run` | Report proposals without writing files |
| `--force` | Overwrite human-set kg fields |
| `--no-cache` | Bypass the proposal cache |
| `--no-validate-graph` | Skip the SHACL graph guardrail on proposals |
| `--max-cost <usd>` | Stop proposing past this cost |
| `--min-confidence <n>` | Minimum model confidence (0..1) to write a field (default: config, 0.7) |
| `--provider <name>` | Provider: anthropic \| openai \| claude-cli \| mock |
| `--model <model>` | Model override |

### Examples

```sh
dockg fill --dry-run --max-cost 0.50    # look before writing
dockg fill "docs/api/**/*.md"           # a subset, for real
dockg fill --provider mock              # offline, deterministic
```

<Aside type="caution" title="Exit 0 does not mean everything was written">
  Fields dropped for low confidence and proposals rejected by the graph guardrail are **routine
  operation**, and the run still exits `0`. Only a per-document `error` status exits `1`. This is
  deliberate, so an orchestrating script does not read a normal run as a failure — but it means
  you must read the report rather than the exit code.
</Aside>

## `query`

Match triple patterns against the built graph (omit a term for wildcard).

### Options

| Option | Description |
|---|---|
| `-s, --s <term>` | Subject IRI or prefixed name |
| `-p, --p <term>` | Predicate IRI or prefixed name |
| `-o, --o <term>` | Object IRI, prefixed name, or literal value |
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

### Examples

```sh
dockg query -p dcterms:title                     # every title
dockg query -p rdf:type -o dockg:Section         # every section node
```

Always exits `0`, including when nothing matched.

## `stats`

Summarize the built graph: counts, orphans, broken links, hubs, metadata coverage.

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |
| `--check` | Exit 1 when broken internal links exist or coverage is below threshold |
| `--top <n>` | How many most-connected docs to list |
| `--coverage-threshold <pct>` | Minimum metadata coverage % (all fields); overrides config for this run |

### Examples

```sh
dockg stats                                  # report only, always exits 0
dockg stats --check                          # gate on config thresholds
dockg stats --check --coverage-threshold 80  # gate on 80% across all fields
```

`--coverage-threshold` applies one number to every field. A per-field map is config-only; see
[`stats.coverageThreshold`](/dockg/reference/configuration/).

<Aside type="caution" title="An empty graph is vacuously 100% covered">
  A gate that passes because a misconfigured `inputs` glob ingested nothing is worse than no gate.
  Check the document count as well as the percentage.
</Aside>

## `search`

Rank graph nodes for a text query (needs `export --format search`).

### Arguments

| Argument | Description |
|---|---|
| `query` | Text query |

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-i, --index <path>` | Search index path (default: `search.json` beside the graph) |
| `--limit <n>` | Maximum results (default 10) |
| `--vectors <path>` | Vector sidecar path (default: config `embed.out`) |
| `--mode <mode>` | Which legs to run: lexical \| vector \| hybrid (default: hybrid when vectors exist) |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

A missing embedder degrades to lexical — unless `--mode vector` or `--mode hybrid` was requested
explicitly, which errors instead. A stale sidecar is refused rather than ranked with.

## `traverse`

Walk the graph from a node, honoring scope rules, with the full trace.

### Arguments

| Argument | Description |
|---|---|
| `node` | Starting node: a full IRI or a prefix:local CURIE |

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-d, --depth <n>` | Maximum hops from the node (default 1; 3 under `--impact`) |
| `--predicates <curies...>` | Only follow these predicates |
| `--reverse` | Follow inbound edges (who points at this node) |
| `--impact` | Transitive inbound reach: what a change here affects |
| `--variant <variant>` | Scope filter: product variant IRI, title, or slug |
| `--subject <subject>` | Scope filter: software subject |
| `--limit <n>` | Stop after this many nodes |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

`rdf:type` is not followed by default. An unknown node, variant, or subject exits `2` rather than
returning an empty set — an unresolvable filter would otherwise return exactly what it was meant
to exclude.

## `embed`

Compute local embeddings for the search index (needs @huggingface/transformers).

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-i, --index <path>` | Search index path (default: `search.json` beside the graph) |
| `-o, --out <path>` | Vector sidecar path (default: config `embed.out`) |
| `--model <id>` | Embedding model id (any id; `mock` for offline runs) |
| `--dtype <dtype>` | Weight quantization (default q8) |
| `--no-cache` | Ignore the vector cache |
| `-f, --format <format>` | Output format: pretty \| json (default: `"pretty"`) |

Local-only by contract: no API, no key, no spend, and no corpus text leaves the machine.
`@huggingface/transformers` is an optional peer dependency, so `embed` exits `2` with an install
hint when it is absent.

## `export`

Reserialize the built graph into a consumer format (jsonld file, iirds package, or search index).

### Options

| Option | Description |
|---|---|
| `-c, --config <path>` | Path to `dockg.config.yaml` |
| `-g, --graph <path>` | Graph `.ttl` path (default: config `out`) |
| `-f, --format <format>` | Export format: jsonld \| iirds \| search (default: `"jsonld"`) |
| `-o, --out <path>` | Output path (default: the graph path with the format's extension) |

<Aside type="caution" title="`-f` means something different here">
  On `export`, `-f/--format` selects the **export format**. On every other command it selects how
  output is rendered (`pretty` or `json`). This is the flag people get wrong.
</Aside>

Projection warnings go to stderr and do not fail the run, so check stderr if you care whether
something was dropped.
