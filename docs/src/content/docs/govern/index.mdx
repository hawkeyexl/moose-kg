Metadata quality decays unless something enforces it. dockg has three gates, they catch different
things, and picking the wrong one wastes a week.

## The three gates

| Gate | Scope | Catches | Exits 1 when |
|---|---|---|---|
| `dockg validate` | One file at a time | Frontmatter that violates the JSON Schema — wrong type, bad enum value, `broader` without `label` | Any file fails |
| `dockg check` | The whole assembled graph | Cross-document problems: `broader` cycles, `related`/`broader` conflicts, applicability contradictions, untyped relation targets | Any finding is a violation |
| `dockg stats --check` | Aggregate numbers | Broken internal links, broken section refs, coverage below threshold | Any threshold is breached |

They are complementary, and most teams end up running all three.

<Aside type="note" title="Why per-file validation is not enough">
  A `skos:broader` cycle spanning three documents is invisible to a per-file check by
  construction — each file is individually valid. Only the assembled graph shows it. That is what
  `check` is for, and it is the reason two validation layers exist rather than one.
</Aside>

## Obligations, and what satisfies them

If you are specifying a requirement for someone else to implement, this is the table to forward.

| Obligation | Mechanism | Command |
|---|---|---|
| Every document carries a title and description | Coverage thresholds per field | `dockg stats --check` |
| Metadata conforms to our schema | JSON Schema validation | `dockg validate` |
| The vocabulary has no cycles or conflicts | SHACL shapes | `dockg check` |
| No topic contradicts itself about applicability | SHACL disjointness | `dockg check` |
| Documentation does not link into nothing | Broken-link detection | `dockg stats --check` |
| Authorship and derivation are recorded | PROV-O derivation | `dockg build`, then query |
| Machine-generated fields are identifiable | `kg.provenance` entries | `dockg build`, then query |
| The same evidence regenerates identically | Determinism contract | Any of the above |

## Read the exit codes before you wire anything

The contract is `0` success, `1` findings, `2` operational error — but four cases report a problem
and still exit `0`, and each one will bite a gate that assumes otherwise:

- `check` with warnings but no violations.
- `build` warning that git history is unavailable.
- `stats` without `--check`.
- `fill` dropping low-confidence fields.
