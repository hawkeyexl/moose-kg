An auditor asks who authored a procedure, when it was last revised, what it was derived from, and
whether a machine wrote any of it. Today that answer is assembled by hand from git history and a
spreadsheet.

This page is about producing it with one reproducible command.

## Why reproducibility is the point

For most readers, byte-identical rebuilds are a convenience that keeps diffs clean. Here it is what
makes the output **evidence**.

A report that changes between runs over unchanged inputs cannot be submitted. One that does not can
be regenerated in front of the person asking, from inputs they can see. moose-kg emits no wall-clock
time, no blank nodes, and no unordered output precisely so that this holds — see
[determinism](/moose-kg/concepts/determinism/).

## What is derived, and from where

| Assertion | Source | Requires git? |
|---|---|---|
| `dcterms:creator`, `prov:wasAttributedTo` | Frontmatter `author` / `authors` | No |
| `dcterms:created`, `prov:generatedAtTime` | Frontmatter `date` / `created`, else git | Falls back to git |
| `dcterms:modified` | Frontmatter `updated` / `lastmod` / `modified`, else git | Falls back to git |
| `prov:wasRevisionOf` | `kg.revisionOf`, plus git rename detection | For the derived half |
| `prov:wasDerivedFrom` | `kg.derivedFrom` | No |
| `prov:wasGeneratedBy` | `kg.generatedBy` or page-level `generatedBy` | No |
| Qualified attribution and association | Derived from the above | No |

## The tri-state git setting

```yaml title="moose.config.yaml"
kg:
  provenance:
    git: auto    # auto | true | false
```

| Value | Behavior |
|---|---|
| `auto` (default) | Derive from git where possible; warn on stderr and continue when not |
| `true` | Require git — exit `2` if history is unreadable |
| `false` | Never shell out to git |

<Aside type="caution" title="`auto` produces a successful build with missing evidence">
  A build in a shallow clone, an exported archive, or a container without git history warns and
  **still exits 0**. If provenance is an obligation rather than a nicety, set `provenance.git: true`
  so a missing history fails the build instead of quietly producing a thinner graph.

  This is also why two builds of the same corpus — one with git, one without — are not
  byte-identical. Determinism holds for a fixed set of inputs, and git history is an input.
</Aside>

## Qualified attribution, and why it is not just a name

A `dcterms:creator` string answers "whose name is on this". It does not distinguish the person who
wrote a document from the tool that generated it from the model that proposed one of its fields —
and that distinction is exactly what an AI-authorship question is asking about.

With `provenance.qualified: true` (the default), moose-kg emits attribution and association nodes
carrying **roles**, so the graph separates:

- a **person** who authored, via `moose-kg:authorRole`
- a **software agent** that generated, via `moose-kg:generatorRole`
- the **tool** that built the graph, via `moose-kg:toolRole`

Agent IRIs are segmented by kind — `agent/person/…`, `agent/software/…`, `agent/org/…` — so a
person and a tool that happen to share a name never collide into one node.

## The machine-authorship record

`moose-kg fill` writes one `kg.provenance` entry per model, naming the fields it proposed and its
confidence in each:

```yaml title="docs/api-keys.md"
kg:
  provenance:
    - generatedBy: claude-opus-4-6
      fields: [prefLabel, topicType]
      confidence:
        prefLabel: 0.92
        topicType: 0.81
```

**Humans delete entries as they review them.** The block is an outstanding-review queue rather than
a permanent ledger, which is the framing worth carrying into an audit conversation: the presence of
an entry means "a machine proposed this and nobody has checked it yet."

Fields union across runs, and one model's entries are preserved when another model runs.

## Query it

```sh
moose-kg traverse "https://docs.example.com/kg/doc/docs/api-keys.md" --predicates prov:wasAttributedTo prov:wasGeneratedBy
```

```sh
moose-kg query -p prov:wasAttributedTo --format json > attribution.json
```

For an impact question — what a change to this document affects — walk inbound edges:

```sh
moose-kg traverse "https://docs.example.com/kg/doc/docs/api-keys.md" --impact
```

## What this evidence does not prove

Worth stating plainly, because overclaiming here is worse than underclaiming.

moose-kg records what your files and git history **assert**. It does not verify that the named author
wrote the text, it cannot tell a `kg.provenance` entry deleted after careful review from one
deleted to clear a warning, and a document with no author simply has no attribution rather than an
anonymous one.

The mechanism supports an audit. It does not replace one.
