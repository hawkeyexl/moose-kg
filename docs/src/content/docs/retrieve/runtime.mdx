`dockg/runtime` is a browser-native, retrieval-only module. It has no `node:` imports, ships as a
single small bundle, and keeps embeddings behind a separate entry point so the query path never
pulls in the model stack.

It never calls a model. It returns results and stops.

## Install and import

```ts
import {
  GraphIndex,
  createLexicalIndex,
  createVectorIndex,
  findEntry,
  traverse,
  assemble,
  createFetchResolver,
} from "@hawkeyexl/dockg/runtime";
```

Embeddings live behind their own specifier, so importing the runtime does not drag them in:

```ts
import { createLocalEmbedder } from "@hawkeyexl/dockg/embed";
```

## The shape of a query

Four stages, each of which you can inspect:

1. **Entry** — rank nodes for the query text, lexically and/or by vector, and fuse the rankings.
2. **Traverse** — walk the graph from those seeds, honoring a scope filter.
3. **Assemble** — resolve the reached nodes to text and build the bundle.
4. **Return** — hand back `{ entry, context, citations, trace }`.

```ts
const graph = new GraphIndex(await (await fetch("/kg/graph.ttl")).text());
// One index per language (ADR 01038). Fetch the manifest first to learn which
// localizations exist, then load only the one you want.
const manifest = parseLocalizations(
  await (await fetch("/kg/localizations.json")).text(),
);
const de = manifest.languages.find((l) => l.language === "de");
const lexical = createLexicalIndex(
  await (await fetch(`/kg/${de.search.path}`)).json(),
);

const entry = findEntry(lexical, "reset the interlock", { limit: 5 });

const { nodes, trace } = traverse(graph, {
  seeds: entry.merged.map((c) => c.iri),
  depth: 2,
  variant: "SP-X100",
});

const bundle = await assemble(graph, nodes, {
  resolve: createFetchResolver("/docs/"),
  maxChars: 8000,
  trace,
  entry,
});
```

## What comes back

```ts
interface RetrievalBundle {
  entry?: EntryRankings;      // lexical, vector, and merged rankings
  context: ContextBlock[];    // resolved text, nearest-first
  citations: Citation[];      // { iri, title?, sourceUrl }
  trace: QueryTrace;          // entry, hops, exclusions, resolutions
  refusal?: Refusal;          // present when nothing usable was found
  truncated: boolean;         // true when maxChars dropped eligible blocks
}
```

Two things are deliberate and easy to miss:

**`entry` is returned, not just traced.** Retrieval answers two different questions — what matched
the query, and what the graph connects to it — and a consumer needs both. The rankings are a result
surface, not diagnostics.

**A refusal is a result.** When nothing usable is found you get `refusal` with a reason
(`no-route` or `no-content`) and an empty `context`, rather than an exception or a plausible-looking
empty answer.

## Scope filters

```ts
traverse(graph, { seeds, depth: 2, variant: "SP-X100" });
traverse(graph, { seeds, depth: 2, subject: "architecture" });
```

A variant may be an IRI, a `dcterms:title`, or a slug. Both polarities are honored: a node is
excluded when it is explicitly marked non-applicable, and — following
[open-world semantics](/dockg/concepts/open-world/) — an untyped node is *not* silently treated as
excluded.

<Aside type="caution" title="Check the exclusions, not just the results">
  The value of a scope filter is what it removed. A traversal returning plausible results while
  dropping nothing is indistinguishable from an unfiltered one. `trace.exclusions` records every
  node the filter removed and why — assert on it in tests.
</Aside>

## `rdf:type` edges are not followed

By default, traversal does not walk `rdf:type` into class nodes, and the reason is the whole point
of the tool: every document shares `dockg:Document`, so traversing type edges makes every document
reachable from every other in two hops. That is exactly the edge contamination graph-governed
retrieval exists to prevent.

`includeTypeEdges: true` exists, and you almost certainly do not want it.

## The trace

```ts
interface QueryTrace {
  entry: EntryCandidate[];
  hops: Hop[];
  exclusions: ScopeExclusion[];
  resolutions: Resolution[];
}
```

Every returned node must be explainable by a recorded event — the traversal's results are a subset
of `reachedNodes(trace)`. That is a contract, not a convention, which is what makes the trace usable
as a reviewer-facing artifact rather than debug output.

## What it does not do

It does not call a model, build a prompt, chunk documents, or have an opinion about your LLM. It
also cannot filter by metadata your corpus does not carry — see the
[dependency stated on the track overview](/dockg/retrieve/).
